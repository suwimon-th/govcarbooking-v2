# วันลาคนขับ — รุ่นทดลอง local

เปิดด้วย `npm run dev:supabase` แล้วเข้า http://localhost:3100/admin/drivers/leaves โดย ADMIN หรือผู้มีสิทธิ์จัดการคนขับ

คนขับเข้า `/driver/leave` ผ่าน LINE และต้องผูก `drivers.line_user_id` แล้ว หน้าใหม่ตรวจ LINE access token ฝั่งเซิร์ฟเวอร์ ไม่เชื่อ driver_id จาก URL ต้องมี LIFF/LINE Login channel ที่ตั้งค่าไว้และ URL callback ที่ LINE เข้าถึงได้ การเปิด localhost บนโทรศัพท์หมายถึงเครื่องโทรศัพท์ ไม่ใช่เครื่องพัฒนา ทดลองหน้าจอและวันลาแทนคนขับได้จากหน้าแอดมินก่อน

- ลาเต็มวันรวมวันสุดท้ายจนถึงเที่ยงคืนวันถัดไป หรือเลือกช่วงเวลาประเทศไทย
- มีผลทันที ไม่ผ่านอนุมัติ คนขับยกเลิกได้ก่อนเริ่มลา แอดมินยกเลิกแทนได้
- หากต้องแก้วันลา ให้ยกเลิกแล้วเพิ่มใหม่ รุ่นนี้เก็บผู้สร้างและผู้ยกเลิกไว้
- งานที่ชนวันลาแสดงให้จัดคนขับแทน ไม่มีการแก้ไขงานเก่าโดยอัตโนมัติ
- กรองรายชื่อใน DriverQueueModal และ EditBookingModal ตรวจซ้ำใน manual/next/auto/retry assignment, create/update booking และ driver accept
- เวลาชนใช้ช่วง [เริ่ม,สิ้นสุด) งานไม่มีเวลาสิ้นสุดสมมติ 60 นาทีตาม flow จองเดิม

วันลาเก็บเฉพาะ `.local/driver-leaves.json` (ถูก gitignore) ไม่สร้างตารางหรือเปลี่ยน RLS ใน Supabase เปิดใช้อัตโนมัติเฉพาะ next dev; production ปิดฟีเจอร์นี้ ข้อมูลรถ/คนขับ/งานยังอ่านจาก Supabase ที่ตั้งค่าไว้ **การกดมอบหมายงานบน local ยังแก้ไข bookings จริงและอาจส่งการแจ้งเตือนเดิม** ทดสอบเพิ่ม/ยกเลิกวันลาและดูตัวกรองได้โดยไม่กดมอบหมายงานจริง

ก่อนใช้งาน prod ต้องย้าย storage ไปตารางฐานข้อมูล แยกสิทธิ์หน้าย่อยหากต้องการ และทำธุรกรรม/locking ให้การแจ้งลากับมอบหมายพร้อมกันไม่เกิด race condition ปัจจุบัน lock ในหน่วยความจำป้องกันการเขียนวันลาพร้อมกันเฉพาะ process เดียว ไม่ครอบคลุม assignment หรือหลาย instance ยังไม่ใช่ implementation สำหรับ deploy

ทดสอบ: `npm run test:driver-leaves` ตรวจวงจรเพิ่มลา/ลาซ้ำ/ขอบเขตเวลา/เจ้าของรายการ/ยกเลิก/ปิดใน production ด้วยไฟล์ชั่วคราว ไม่แตะข้อมูลจริง ยังไม่ได้ทดสอบ LINE end-to-end

## เมนูและสิทธิ์หน้าย่อย

หน้าวันลาใช้คีย์ `drivers.leave` แยกจาก `drivers` แล้ว กำหนดที่หน้าจัดการสิทธิ์ → คนขับรถ → วันลาคนขับ ผู้มีสิทธิ์คนขับเดิมไม่ได้รับสิทธิ์วันลาเพิ่มอัตโนมัติ ADMIN เข้าถึงได้ตามเดิม

ใช้ `scripts/add_driver_leave_permission.sql` หลัง migration สิทธิ์เดิมเพื่อขยาย constraint โดยไม่เปลี่ยน grants ของผู้ใช้ เมนู sidebar และแท็บคนขับอ่าน `PERMISSION_MODULES`/`PERMISSION_SECTIONS` ชุดเดียวกัน การเพิ่มหน้าย่อยต้องเพิ่มคีย์/เส้นทาง/API requirement และขยาย constraint ก่อนบันทึกสิทธิ์ใหม่
